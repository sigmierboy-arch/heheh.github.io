🔧 Валидация HTML и инструменты разработчика (DevTools)

🎯 Цель урока

Научиться проверять HTML-код на ошибки с помощью валидатора W3C и отлаживать страницу через DevTools.

📚 Теория

  1. Валидатор W3C
    Заходишь на validator.w3.org, вставляешь код или URL. Получаешь список ошибок и предупреждений. Исправляешь. Повторяешь. Цель — зелёная полоска! ✅
  2. Инструменты разработчика (F12)
    • Elements (Инспектор): живое DOM-дерево, можно править HTML/CSS на лету
    • Console: ошибки загрузки и скриптов
    • Можно кликнуть правой кнопкой на элемент → «Посмотреть код»

🔍 Разбор кода по косточкам:

  • Валидатор W3C — «проверка орфографии» для HTML
  • DevTools → Elements — микроскоп для твоей страницы
  • Консоль — красные сообщения = ошибки

💡 Полезный совет:

Всегда открывай DevTools (F12), когда что-то идёт не так. Не гадай — смотри реальную структуру, которую видит браузер!

⚠️ Типичная ошибка:

Игнорировать инструменты и гадать «на глаз». «Съехал блок — наверное, марджин поменять». А на самом деле забыт закрывающий <div>. DevTools покажет правду!

✅ Итоги урока:

  • Валидатор W3C — проверка синтаксиса
  • DevTools (F12) — отладка в реальном времени
  • Elements — просмотр и правка DOM
  • Console — ошибки

🧠 Самостоятельная работа:

  1. Создай файл с 3-4 ошибками. Проверь через валидатор W3C. Разбери каждую ошибку.

  2. Открой свой проект, нажми F12. Во вкладке Elements измени текст заголовка <h1> — посмотри, как меняется страница.

  3. Используй инструмент выбора элемента (стрелочка в углу DevTools), наведи на блоки — посмотри на размеры и отступы.

🤖 Вопрос к размышлению:

Почему браузер пытается «исправить» и показать страницу с ошибками, а не выдаёт чёрный экран?

🎉 Бонус:

Профи не пишет идеальный код с первого раза. Он умеет его ОТЛАЖИВАТЬ. Ты стал веб-детективом! 🕵️
